# ELO Authorized Specialist Access Acceptance

- [ ] Separate account can be recognized as an authorized specialist principal.
- [ ] Role, domain, enterprise context and scope are explicit.
- [ ] Specialist can consult authorized business information.
- [ ] Specialist can answer domain GAPs and provide technical evidence.
- [ ] Specialist cannot directly promote learning to Core.
- [ ] Specialist cannot alter canonical identity, governance or security policy.
- [ ] Specialist cannot access unrelated repositories through ELO.
- [ ] Consultation credentials are read-only where applicable.
- [ ] Write permissions are narrowly scoped and require governed execution.
- [ ] Unauthorized repository/site access is treated as a security event.
- [ ] No credentials, tokens or secrets are stored in the repository.
