# ELO Forge — Role and Promotion Boundary

**Status:** NORMATIVE

## 1. Canonical boundary

`Cognitico_IA-corporative` is the canonical operational repository for ELO architecture, contracts, implementation, governance, tests and verified knowledge.

`ELO-Forge` is not a second ELO Core and is not a parallel runtime authority.

## 2. Forge may contain

- candidate knowledge;
- domain experiments;
- working documents;
- specialist material;
- prompts and controlled assets;
- historical analysis;
- prototypes that have not yet passed ELO governance.

## 3. Promotion rule

Forge material is promoted only through:

`OBSERVE → CLASSIFY → COMPARE → EVIDENCE → PROMOTE / REUSE / EXTEND / REJECT / ROADMAP → TRACE`

Required classifications:

- REUSE
- EXTEND
- NEW
- ROADMAP
- DUPLICATE
- CONFLICT

No missing fact may be invented to make promotion succeed.

## 4. Knowledge ownership

Validated generalizable mechanics may become ELO Faculty/knowledge under the existing governance lifecycle. Tenant- or context-specific knowledge remains removable as Overlay. Unsupported information remains Gap. Incompatible information remains Conflict until resolved.

## 5. What must not be promoted directly

Do not copy directly into the canonical repository merely because it exists in Forge:

- duplicate architecture documents;
- competing Core implementations;
- competing memory stores;
- competing Orchestrators;
- provider-specific runtime shortcuts;
- unvalidated business assumptions;
- obsolete directory structures;
- generated workspace artifacts.

## 6. Traceability

Every promoted item must retain source provenance, classification, reason for promotion, validation evidence and canonical destination.

## 7. Architectural principle

Forge accelerates discovery. Cognitico establishes canonical truth only after evidence and governance.
