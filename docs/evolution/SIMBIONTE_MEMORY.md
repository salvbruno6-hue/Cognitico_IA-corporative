# ELO — Simbionte Memory

**Status:** FORGE / EVOLUTION LAB / CANDIDATE-ONLY
**Owner:** ELO Cognitive
**Shared faculty:** Core
**Promotion gate:** Evolution_Gate
**Version:** 1.0

## 1. Purpose

This memory defines what the Simbionte must retain about external experiences, how those experiences are related to existing ELO capabilities, and how they may become refined capability candidates.

The Simbionte does not own canonical memory, Core, Soul, routing, authorization or the Evolution Gate. It is a cognitive nature of ELO that absorbs, relates, experiments, measures, refines and generalizes experience.

## 2. Fundamental rule

`RETAIN EXPERIENCE → EXTRACT MECHANISM → RELATE TO EXISTING CAPABILITY → REFINE → TEST → MEASURE → REPEAT → GOVERN`

External implementations are evidence sources, not authorities.

Hermes and OpenClaw must never become competing ELO memories or capability authorities. Their useful mechanisms are retained as provenance-bearing experience and associated with an existing ELO capability.

Historical experience is immutable. Refinement creates a new version or candidate state; it does not rewrite the historical observation.

## 4. What the Simbionte remembers

### Experience

What happened, under which context, with which authorized capability and what evidence was produced.

### Mechanism

The operational principle extracted from the experience, separated from the external implementation.

### Relationship

The existing ELO capability that can absorb the mechanism.

### Adjustment

The precise logical, contextual and governed modification proposed for the existing capability.

### Result

What changed after the adjustment and whether the change produced measurable benefit.

### Failure

Gaps, conflicts, blocked executions, regressions, redundancy, insufficient evidence and unsafe scope are retained as useful negative evidence.

## 5. Refinement memory

The Simbionte must remember the progression:

`baseline → adaptation v1 → test → result → diagnosis → adaptation v2 → retest → ... → refined candidate`

A failed refinement is not erased. It becomes evidence that informs the next adjustment.

The Simbionte must preserve why an adjustment was made, what evidence justified it, what metric was expected to improve and what actually happened.

## 6. Association rule

The primary relation is:

`contexto → necessidade → capacidade ELO → skill → mecanismo → execução → resultado`

Association requires comparable evidence, compatible context, preserved provenance and the same tenant boundary. Lexical similarity alone is insufficient.

When an existing ELO owner is identified, the disposition is `REUSE`, `STRENGTHEN` or `REFACTOR`; `CREATE` is exceptional and requires demonstrated absence of an appropriate owner plus successful generalization.

## 9. Memory quality rules

The Simbionte must prefer:

1. explicit evidence over inference;
2. reproducible outcomes over isolated success;
3. measured gain over subjective improvement;
4. existing capability reuse over structural duplication;
5. immutable provenance over reconstructed history;
6. explicit uncertainty over invented certainty;
7. negative evidence over silent failure;
8. controlled refinement over uncontrolled mutation.

## 10. Prohibited memory behavior

The Simbionte memory must not:

- silently rewrite canonical knowledge;
- promote an external mechanism automatically;
- merge incompatible tenant experiences;
- infer authorization;
- alter Soul or Core;
- replace canonical routing;
- create a competing Memory or Evolution Gate;
- treat one successful execution as generalized learning;
- delete failed experiments to improve apparent performance.

## 11. Evolution criterion

An experience becomes a credible evolution candidate only when the record contains:

`PROVENANCE + CONTEXT + BASELINE + MECHANISM + ADAPTATION + EXPERIMENT + OUTCOME + METRICS + REGRESSION + GENERALIZATION + RISK + OWNER`

The memory stores the evidence. Governed Learning evaluates it. Evolution Gate decides whether the resulting capability may become canonical.
