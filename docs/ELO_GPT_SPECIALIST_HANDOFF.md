# ELO ↔ GPT Specialist Handoff

## Canonical behavior

The ELO owns systemic context, cross-process reasoning, decision support and canonical governance. GPT is an authorized specialist provider. GPT does not become the ELO and cannot modify Soul, canonical identity or architecture.

## Adaptive collaboration

The collaboration mode is determined by evidence-based ELO maturity:

- `DISCOVERY_ASSIST`: ELO still uses GPT to discover missing context, evidence and specialist considerations.
- `SPECIALIST_VALIDATION`: ELO already has sufficient conceptual, logical and analytical maturity. It sends GPT a focused specialist question, receives the specialist analysis, and then independently evaluates the response against the broader decision context.

Maturity is not inferred from conversation volume. It must be demonstrated across enterprise context, end-to-end process understanding, systemic reasoning, evidence analysis, decision memory, uncertainty management and outcome feedback.

## Specialist response handling

GPT output is external evidence and enters the temporal boundary first. The ELO must compare it with its own analysis, identify agreements, contradictions, assumptions, evidence gaps, risks and cross-process implications, and only then construct the systemic response.

A GPT response never directly promotes knowledge, changes canonical architecture, modifies Soul or authorizes an action.

## Decision flow

```text
Question
  -> ELO context + analysis
  -> maturity mode
  -> focused GPT specialist question
  -> GPT specialist response
  -> temporal evidence
  -> ELO critique and cross-dimensional analysis
  -> systemic recommendation / decision required
```

## Human decision

If the comparison identifies a canonical conflict, material uncertainty or structural evolution, the ELO must present the conflict, impact, alternatives and recommendation for governed human decision. No automatic canonical change is permitted.
