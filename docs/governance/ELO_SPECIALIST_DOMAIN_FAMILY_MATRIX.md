# ELO Specialist Domain Family Matrix

## Purpose

Canonical governance representation of Forge technical specialist families. This matrix does not create new Core authority or production runtime behavior.

## Architectural ownership

- ELO Cognitive: identity, principles, invariants, authority and promotion rules.
- Core: shared cognitive faculty, generalized and validated learning, general mechanisms.
- Forge: technical specialists, domain skills, contextual knowledge, parameters, experiences and company overlays.
- Application / Infrastructure: replaceable means of manifestation and execution.

## Domain families

| Domain family | Canonical Forge owner | Initial maturity | Core role |
|---|---|---|---|
| PCP | Forge PCP Specialist | applied source connected | shared faculty/mechanisms |
| Budgeting | Forge Budgeting Specialist | governed capability connected | shared faculty/mechanisms |
| HR | Forge HR Specialist | family represented; skill implementation pending | shared faculty/mechanisms |
| Calculation | Forge Calculation Specialist | family represented; skill implementation pending | shared faculty/mechanisms |

## Rules

1. A domain specialist is not a second Core or independent canonical intelligence.
2. Domain technical knowledge remains in Forge until generalized and validated.
3. External courses, plugins and sources are learning sources, not canonical authority.
4. Company-specific parameters and experiences remain contextual in Forge.
5. Only generalized, validated learning may be proposed for Core promotion through the existing Evolution Gate.
6. Original experiences remain preserved in Forge after promotion.
7. Missing specialist implementation is a GAP, not permission to invent capability.

## Next specialist progression

PCP is the reference applied Skill Pack. Budgeting is the existing ELO-024 governed capability with Forge specialist context. HR and Calculation are represented as governed families and must use the same Skill Registry contract when implemented.
