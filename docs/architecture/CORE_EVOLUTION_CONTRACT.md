# ELO Core — Evolution Contract

## Objective

Define how the Core evolves without becoming a repository of every enterprise experience.

## Promotion pipeline

```text
Forge experience
  → analysis
  → evidence
  → validation
  → generalization assessment
  → Core candidate
  → governance decision
  → Core knowledge/parameter
```

## What remains in Forge

- enterprise-specific rules;
- contextual parameters;
- specialist operating methods;
- individual cases;
- unresolved hypotheses;
- complex end-to-end experiences;
- evidence and feedback history;
- company-specific decisions and outcomes.

## What may enter Core

Only validated knowledge or parameters that demonstrate applicability beyond the originating case and do not violate the ELO Cognitive canon.

## Complex experiences

A complex experience may involve multiple sectors, specialists, decisions, dependencies and material outcomes. The complete experience remains in Forge. Core receives only the validated generalized learning derived from it.

## Parameter requirements

A promoted general parameter must retain:
- definition;
- unit/type;
- scope of applicability;
- validation evidence;
- source experience reference;
- validation date/version;
- confidence/status;
- governance state;
- conditions under which it is valid.

A contextual parameter is not a general parameter merely because it was useful once.

## No silent promotion

No scheduled analysis, specialist, application or connector may directly mutate canonical Core knowledge. Promotion is an explicit governed transition.

## Reversal

If later evidence invalidates a Core parameter or knowledge item, the historical record remains immutable. The current state is superseded/revoked through governance; history is not erased.
