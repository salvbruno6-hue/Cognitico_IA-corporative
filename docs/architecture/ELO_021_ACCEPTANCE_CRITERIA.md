# ELO-021 — Architecture Acceptance Criteria

## Canonical separation

- [ ] ELO Cognitive is the only canonical identity/essence authority.
- [ ] Core is the governed evolutionary intelligence.
- [ ] Forge owns contextual enterprise experience and specialist operations.
- [ ] Application/infrastructure cannot redefine canonical authority.

## Memory and learning

- [ ] Original experience remains immutable after feedback.
- [ ] Source provenance points to the originating excerpt/record only.
- [ ] Follow-ups remain linked until feedback is received.
- [ ] Contextual parameters remain in Forge unless generalized and validated.
- [ ] Complex end-to-end experiences remain preserved in Forge.
- [ ] Core promotion is explicit, governed and reversible without deleting history.

## Decoupling

- [ ] Removing a specialist does not corrupt Core.
- [ ] Removing a Forge module does not corrupt ELO Cognitive identity.
- [ ] Replacing an infrastructure adapter does not require changing cognitive contracts.
- [ ] No parallel authority is introduced by integrations.

## Multi-enterprise safety

- [ ] Company-specific knowledge remains scoped to its enterprise context.
- [ ] Enterprise versioning is preserved in Forge.
- [ ] Cross-company generalization requires validation rather than implicit copying.

## Required evidence before merge

The implementation must provide repository evidence for each criterion above. Documentation alone is insufficient where an executable test can be written. Any failing criterion blocks promotion to main.
