# ELO Governed Learning Laboratory

## Purpose

Provide one tenant-scoped staging boundary for operational experiences, specialist outputs, agent outcomes, external AI results, plugin results, calculations and corrections without making them canonical automatically.

## Canonical lifecycle

`EXPERIENCE → CANDIDATE → VALIDATED → PROMOTED`

`REJECTED` is terminal for an invalid candidate or validated observation.

- New observations enter as `EXPERIENCE`.
- Evidence is mandatory before `CANDIDATE`.
- Validation is mandatory before `PROMOTED`.
- Promotion remains subject to existing governance and Evolution Gate authority.

## Symbiotic learning

The laboratory records enough provenance to compare specialist, provider, model, tool, context, instruction and method performance for classes of mission. It must inform routing through validated evidence rather than hard-coded provider/domain assignments.

## Boundaries

The laboratory is not a second Core, canonical memory, provider registry, supervisor or Evolution Gate. External AI output is non-canonical by default. It cannot rewrite Soul, Core contracts or canonical rules by inference.

## Tenant and provenance

Every observation is scoped to a tenant and retains its source type, problem, result and evidence references. Tenant retrieval must never cross the tenant boundary. Provider credentials are never learning observations.

## Integration order

The first integrated use case is budgeting. Agent and workflow outcomes feed observations; validated observations can later inform the canonical `ExecutionRouter`. The router remains the canonical execution-selection authority.

## Status

This contract is the convergence-branch implementation target. It intentionally does not claim automatic semantic retrieval, provider ranking, autonomous promotion or a complete workspace UI.
