# ELO — Canonical Boundaries

## Purpose

Define the stable separation between the ELO Cognitive soul, the Core evolutionary mind, the Forge experiential ecosystem, and external application/infrastructure.

## 1. ELO Cognitive — Soul / Canon

The ELO Cognitive is the canonical identity and essence of ELO. It contains what must remain recognizably ELO regardless of company, platform, specialist, interface, connector, or infrastructure.

It owns:
- canonical identity and principles;
- canonical invariants;
- essence and non-negotiable behavioral commitments;
- canonical boundaries and authority rules.

It does **not** absorb company-specific operating rules or infrastructure details.

## 2. Core — Evolutionary Mind / Intelligence

The Core is the canonical evolutionary intelligence governed by the ELO Cognitive canon.

It owns:
- intelligence and reasoning mechanisms;
- generalized knowledge validated for reuse;
- general parameters;
- personality and behavioral configuration within canonical limits;
- contracts;
- governance;
- systemic evolution mechanisms;
- canonical cognitive memory and evolution history.

A company experience does not enter the Core merely because it was observed. Promotion requires validation and generalizability.

## 3. Forge — Experiential Ecosystem

Forge contains the physical/operational expression of ELO in organizations.

It owns:
- specialists and specialist capabilities;
- operational skills and workflows;
- enterprise contexts and direction;
- company-specific versioning;
- experiences, evidence, decisions and results;
- contextual parameters;
- follow-ups and feedback;
- complex end-to-end experiences;
- ELO App modules adapted to enterprise contexts.

A complex, high-impact, multi-sector experience remains preserved in Forge even when it produces generalized learning for Core.

## 4. Application and Infrastructure

Applications and infrastructure are means of access and execution, not sources of canonical authority.

They may include ERP, CRM, BI, Git, databases, APIs, connectors, agents, interfaces and deployment platforms.

They must consume contracts rather than modify Core or the ELO Cognitive canon directly.

## 5. Authority rule

```text
ELO Cognitive → defines what ELO is
Core          → defines generalized evolutionary intelligence
Forge         → contains contextual experience and specialization
Application   → presents/operates the ELO for a context
Infrastructure→ provides technical execution and connectivity
```

No lower layer may silently redefine a higher layer.

## 6. Safe detachment

Removing a Forge specialist, enterprise module, application or infrastructure connector must not corrupt ELO Cognitive identity or Core canonical integrity. Contextual memory may become unavailable with the detached integration, but canonical history and validated Core knowledge must remain intact.
