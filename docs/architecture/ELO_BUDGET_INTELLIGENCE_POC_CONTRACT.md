# ELO Budget Intelligence — Integrated POC Contract

## Purpose

Validate the simultaneous convergence of the ELO layers using budgeting as the first real mission.

## Canonical flow

`TENANT → MISSION → CONTEXT → CAPABILITY → EXECUTION ROUTER → INTELLIGENCE ROUTER → PROVIDER/TOOL → EVIDENCE → BUDGET → CRITIQUE → DECISION → OUTCOME → LEARNING LAB → EVOLUTION GATE`

## Reuse rule

The POC MUST reuse the existing governed budgeting capability, existing evidence/provenance contracts, existing ExecutionRouter, existing governed AI provider adapter, existing agent/workflow runtime and existing learning governance. It MUST NOT create a second budget engine, router, memory authority, provider registry or Evolution Gate.

## Mission record

Every POC execution must preserve at minimum:

- request and tenant identity;
- specialist and capability selected;
- routing decision and rationale;
- provider and model;
- supplied corporate context;
- evidence identifiers and provenance;
- budget version and formula version;
- critique and authorization state;
- final result;
- expected and observed outcome when available;
- learning observation identifier.

## Budget safety

Missing information remains a GAP. Conflicting evidence remains a CONFLICT. The system must not invent missing budget inputs. Recommendation remains distinct from approval, commitment and execution.

## Learning boundary

The POC records the execution as experience before any learning candidate is proposed. A provider response is evidence-bearing experience, not canonical knowledge. Promotion requires validation and the existing Evolution Gate.

## Success criteria

The first integrated run is successful only if the complete provenance chain can be reconstructed and tenant isolation is preserved. A successful calculation alone is insufficient.

## Failure behavior

If identity, routing, provider authorization, evidence, required budget inputs or governance state is invalid, the mission must stop with an explicit blocked/conditional result and preserve the reason for later analysis.
