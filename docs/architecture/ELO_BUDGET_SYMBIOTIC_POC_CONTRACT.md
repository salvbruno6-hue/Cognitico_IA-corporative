# ELO Budget Symbiotic POC Contract

## Purpose

Validate the simultaneous-layer convergence through the first end-to-end
corporate mission: a governed budget request.

This is an integration contract, not a new budgeting engine, router, memory
system or decision authority.

## Canonical components reused

- `GovernedBudgetingService` — existing Core budgeting capability.
- `ExecutionRouter` — canonical capability/model/tool selection authority.
- `IntelligenceRouter` — interoperability coordinator over `ExecutionRouter`.
- governed AI provider adapters — external cognitive execution.
- Evidence/Provenance contracts — source and traceability boundary.
- Learning Laboratory — non-canonical experience staging.
- existing Evolution Gate — promotion authority.

## Mission record

Every POC execution must preserve:

`request_id → tenant_id → principal_id → objective → specialist → capability → route → provider → model → tool → context → evidence → result → critique → authorization → outcome → experience`

Missing evidence must remain a GAP or BLOCKED condition according to the
underlying capability contract. The AI provider must not invent missing budget
inputs.

## Symbiotic execution

ELO supplies direction, corporate context, governance, evidence requirements,
quality criteria and evaluation. The selected specialist/provider/tool supplies
cognitive or operational execution.

The provider response is an execution result, not canonical corporate truth.

## Learning

After the budget outcome is observed, the ELO may record an experience with:

- mission class;
- specialist;
- provider/model;
- tools;
- context characteristics;
- evidence characteristics;
- result quality;
- corrections;
- expected versus observed outcome;
- provenance.

The experience enters the Learning Laboratory first. Only validated,
generalizable learning may influence routing or canonical knowledge through the
existing governance path.

## Acceptance gates

1. Tenant isolation passes.
2. Budget provenance remains intact.
3. Missing/conflicting inputs are not silently invented or resolved.
4. Recommendation remains separate from approval/commit/execute authority.
5. External AI output remains non-canonical.
6. The canonical `ExecutionRouter` remains the selection authority.
7. Learning is recorded separately from canonical memory.
8. The complete execution trace is reproducible/auditable.
9. No second Core, memory, router, provider registry or Evolution Gate exists.
10. Regression tests pass before merge.

## First learning question

The first POC must not ask only whether the budget was produced. It must also
measure which governed combination of specialist, model, tool, context and
method produced the best validated result for that mission class.
