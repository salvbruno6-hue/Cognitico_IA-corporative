# ELO Governed Learning Laboratory

## Purpose

Create a separated learning area where operational experiences, AI outputs,
calculations, observations, corrections and outcomes can accumulate without
becoming canonical ELO knowledge automatically.

## Lifecycle

`EXPERIENCE → CANDIDATE → VALIDATED → PROMOTED`

A candidate requires evidence. Promotion requires prior validation. Rejected
experiences remain outside canonical knowledge.

## Sources

The laboratory may receive observations from users, specialists, agents,
external AI providers, plugins, calculations, workflows and real outcomes.
The source is recorded as metadata so the ELO can compare methods and results.

## Separation rule

The learning laboratory is not a second Core, canonical memory, policy
authority or supervisor. It is an evidence-bearing staging area for learning.
Canonical promotion remains subject to existing governance and Evolution Gate
mechanisms.

## Tenant boundary

Observations are tenant-scoped. Retrieval must not expose one tenant's
learning observations to another tenant.

## Intended autonomous cycle

The ELO may periodically inspect the laboratory, identify repeated patterns,
compare outcomes and generate learning candidates. It must not promote a
candidate merely because an AI provider suggested it.

## Symbiotic learning

The laboratory supports learning which specialist, provider, model, tool,
context, instruction and method produced better results for a given class of
mission. These observations inform the Intelligence Router without hard-coding
one provider to one domain.
